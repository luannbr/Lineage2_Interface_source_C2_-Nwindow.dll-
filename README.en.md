# Lineage II C2 NWindow.dll — source rebuilt in C++

[Português](README.md) · **English** · [Русский](README.ru.md)

A function-by-function rebuild of the `NWindow.dll` of the Lineage II **Chronicle 2 (Age of Splendor)** client: the
native interface DLL (windows, controls, NPC HTML, IME, chat, console, MSN). The target is the original build of
03/03/2005 (TimeDateStamp `0x4227239B`, Visual C++ .NET 2002 `13.00.9466`, md5 `0111f657…`, 225 native classes, 227
exports, 7,117 functions). It is a fork of the
[C1 project](https://github.com/luannbr/Lineage2_Interface_source_C1_-Nwindow.dll-): the same tools and the same
method, with the source ported to the C2 image (`tools/port/`). The same source builds two ways:

| CMake target | Output | What it is |
|---|---|---|
| `NWindowDecomp` | `build/bin/Release/NWindowDecomp.dll` | **hook mode**: runs next to the original `NWindow.dll` and replaces each reimplemented function with a `jmp` to ours |
| `NWindowStandalone` | `build/standalone/Release/NWindow.dll` | **standalone**: the whole `NWindow.dll`, our code only; what the judges compare with the original |

There is no new-feature layer (C1's "phase 6", `NWindowL2`) in this repository: see
[docs/MODIFY_INTERFACE.md](docs/MODIFY_INTERFACE.md) for how to add one.

## How it works

**Hook mode.** The installer (`tools/install_test.py`) adds to the original `NWindow.dll` an import of
`NWindowDecomp.dll`. It loads before any original code runs and puts a `jmp` at the entry of every function we have
reimplemented (an `NW_HOOK_*` next to each definition, `src/re/NwHook.h`). The rest is still the original code. Any
function can be switched off in `NWindowDecomp.ini` (`[Hooks] Disable=`) to isolate a bug.

**Standalone (phase 5).** With `NW_HOOK_MODE=0` the hook macros are empty and the source builds `NWindow.dll` on its
own: the 225 `UClass`es (`IMPLEMENT_CLASS`, `src/standalone/Classes.gen.cpp`), the globals with the original values
(`NwGlobals.cpp`), the 227 exports with the original ordinals (`NWindow.def`) and the 7 colour cursors. The engine
(`Core.dll`/`Engine.dll`) loads our DLL the way it loaded the original.

Two deliberate differences from the original (details in [docs/notas/C2_Fase5.md](docs/notas/C2_Fase5.md),
Portuguese):
- the third-party nProtect GameGuard library, statically linked into the original (85 functions), **is not part of
  this source**: in the standalone the three entry points the game calls are documented empty functions
  (`include/nwindow/NGameGuard.h`), as in the patched client used as the reference;
- NKeyCrypt (`npkcrypt.dll`, imported by ordinal in the original) is loaded at run time (`LoadLibrary` + ordinal,
  `src/nwindow/NKeyCrypt.cpp`): the standalone works with or without that DLL.

The standalone writes two diagnostic files next to `l2.exe`: `NWindow_crash.log` (only when the process faults:
registers and stack as module+RVA; `python tools/port/map_addr.py <rva>` names them) and `NWindow_trace.log` (clan
events, `NW_TRACE`).

## Status

- Hook mode: **3,451 of 4,652** functions to reimplement are done (**92.08 %** of the code bytes); the verifier
  accepts all of them (a difference only with an explanation in `db/verify_notes.csv`), `regcheck` is clean, no hook
  reaches an `int3` body. Without a hook, for a reason: 416 by convention (*scalar deleting destructors*,
  `InternalConstructor`) and 686 the compiler generates in the standalone (static initialisation, `DllMain`).
  Without a hook and without a reason: 99, of which 85 are the nProtect library and its three callers (left out of
  the standalone) and 14 are tiny bodies folded by the linker. Live count:
  [docs/PROGRESSO.md](docs/PROGRESSO.md) (generated by `tools/build_db.py`).
- Standalone: links, passes `verify_standalone.py` (PE, imports, resources, 227 exports, 225 classes, 227 vtables),
  the smoke test (its output is the original's, line by line), `gen_globals.py --check` (82 globals equal) and was
  used in game against a C2 server (clan and private stores checked in a real session:
  [docs/notas/C2_Pacotes.md](docs/notas/C2_Pacotes.md)).
- Not done yet: the `difftest` (its cases call the original by C1 addresses and `tools/difftest.py` refuses the C2
  image) and `db/verified.csv` (no function marked as tested in game one by one).
- The technical notes (`docs/`) are in Portuguese; code comments are in English.

## Requirements

- Windows, **Visual Studio 2022** with C++ for x86 (MSVC v143), **CMake ≥ 3.20**;
- **Python 3** with `pefile` and `capstone` (`pip install pefile capstone`): used by the standalone build (cursor
  extraction) and by every tool; `unicorn` for the differential tests in `tools/port/emu/`;
- **your own Lineage II C2 client**. No game file is in the repository: copy into `orig/` the files listed in
  [orig/README.md](orig/README.md) (the `NWindow.dll` must have the md5 given there);
- for the judges (`verify_hooks.py`, `regcheck.py`, `verify_standalone.py`, `build_db.py`, `tools/port/*`): the
  Ghidra export in `analysis/ghidra/`, recreated by `bash tools/ghidra/run_full.sh` (Ghidra 11.3.2 and JDK 21; paths
  in `NWD_GHIDRA_HOME` and `GHIDRA_JAVA_HOME`).

## Build

In an x86 VS 2022 *Developer Command Prompt* (or after `vcvars32.bat`), at the repository root:

```bat
cmake -S . -B build -A Win32 -DNWD_GAME_SOURCES=ON
cmake --build build --config Release
cmake --build build --config Release --target NWindowStandalone
```

`-DNWD_GAME_SOURCES=ON` compiles the game source (`src/nwindow`). Without it (the `CMakeLists.txt` default)
`NWindowDecomp` holds only the hook runtime and replaces nothing: it proves the install chain. The first `--build`
produces the hook-mode DLL and the test tools (`nwd_smoke`, `nwd_difftest`) and does not need `orig/`;
`NWindowStandalone` needs `orig/NWindow.dll`. The `'pwsh.exe' is not recognized` line at the end of each project
comes from the Visual Studio environment and does not fail the build.

## Install and test

Use a **copy** of the client's `system` folder, never the one you play from
(`xcopy /E /I /Y "<client>\system" "<client>\system_nwtest"`).

**Hook mode:**

```bat
python tools\install_test.py --system "<client>\system_nwtest"
python tools\install_test.py --system "<client>\system_nwtest" --restore
```

The first writes an `NWindow.dll` rebuilt from `orig/NWindow.dll` with the extra import, `NWindowDecomp.dll` and an
`NWindowDecomp.ini` (the `NWindow.dll` that was there is kept as `NWindow.dll.pre-decomp-bak`); the second puts back
what was there. `NWindowDecomp.log` in that folder lists every installed hook. In the `.ini`: `[Hooks] Enabled=0`
keeps all the original code; `Disable=` takes an address (`1000cc40`), a method (`NCGDevice::DrawText`) or a class
(`NCGDevice::*`); `[Debug] Marker=1` draws marks only our code draws (a yellow line at the top, `#` in the password)
to check that the hooks are live.

**Standalone:** close the game, keep the test folder's `NWindow.dll` aside and copy
`build\standalone\Release\NWindow.dll` over it. Only that file. To go back, put the original back.

**Full cycle** (stops at the first failing step):

```bat
set NWD_CLIENT_SYSTEM=<client>\system_nwtest
python tools\cycle.py --game-source --no-install
python tools\cycle.py --game-source --standalone --no-install
tools\port\cycle.bat
```

`cycle.py` configures and builds `build/`, installs into a minimal copy in `build/smoke_system` (it copies `Core.dll`,
`Engine.dll`, their dependencies and `npkcrypt.dll`/`npkpdb.dll` from the test folder), loads it outside the game,
verifies, runs `regcheck` and regenerates the database; `--standalone` adds the standalone steps; without
`--no-install` it also installs into the test folder (the game running from it must be closed).
`tools\port\cycle.bat` is the cycle every change must pass: `cycle.py --game-source --no-install`, then
`verify_data.py` and `check_breakers.py` (it calls the VS 2022 Community `vcvars32.bat` itself).

**Machine paths.** No tool carries a path of the author's machine: a folder outside the repository comes from the
command-line option or from one of these variables (the option wins; a tool that needs one and has neither stops
and says which):

| Variable | Points to | Used by |
|---|---|---|
| `NWD_CLIENT_SYSTEM` | the test client's `system` folder (a copy: installing writes into it) | default `--system` of `install_test.py`, `cycle.py`, `smoke_standalone.py`, `difftest.py`; `verify_hooks.py --log`; `ue2_layouts.py` (`Engine.u`, `Core.u`) |
| `NWD_GHIDRA_HOME` | the Ghidra install (with `support/analyzeHeadless.bat`; `GHIDRA` still takes precedence) | `tools/ghidra/*.sh`, `tools/c2/ghidra_census.sh` |
| `NWD_C1_ROOT` | a checkout of the [C1 project](https://github.com/luannbr/Lineage2_Interface_source_C1_-Nwindow.dll-) with its own `orig/` and `analysis/ghidra/` | `tools/port/*` (the C1 → C2 port), `tools/c2/compare_nwindow.py`, `tools/ue2_console_slots.py`, `ue2_gamedata_regions.py`, `ue2_ret_diff.py`, `ue2_vtable_diff.py` |
| `NWD_C2_SERVER` | a server's deploy folder (pages in `gameserver/data/html-en`) | `difftest.py`, the `server` page set (skipped without it) |

## The judges

| Judge | Command | What it proves |
|---|---|---|
| smoke | `build\smoke\Release\nwd_smoke.exe build\smoke_system` | the patched `NWindow.dll` loads outside the game and every hook says `ok` (`NWindowDecomp.log`) |
| verify | `python tools/verify_hooks.py --log build/smoke_system/NWindowDecomp.log` | each of our functions against the original in assembly: bytes popped at `ret`, vtable slots and imports called; a difference only with an explanation in `db/verify_notes.csv` |
| regcheck | `python tools/regcheck.py --game-src` | no original caller relies on a register our function may change (the original was built with `/GL`) |
| verify_data | `python tools/port/verify_data.py` | the data each function touches (constants, field offsets, strings) equal to the original's; differences looked at in `db/verify_data_notes.csv` |
| breakers | `python tools/port/check_breakers.py` | no hook reaches a function whose body is `int3` (`NW_UNPORTED`) |
| emu | `python tools/port/emu/t_<name>.py ...` (e.g. `t_nkeycrypt.py 1500 1`) | the original and our function run side by side in unicorn on random inputs and write the same |
| standalone: declarations | `python tools/verify_standalone.py --checks source` | our `NW_DECLARE_CLASS` / `NW_CHECK_VTABLE` against the original class table |
| standalone: verify | `python tools/verify_standalone.py --dll build/standalone/Release/NWindow.dll` | PE, imports, resources, exports, classes and vtables equal to the original's, without running it |
| standalone: smoke | `python tools/smoke_standalone.py --dll build/standalone/Release/NWindow.dll` | loaded the way the engine loads it: classes registered, `ConsoleWnd`/`L2Font` constructed, output equal to the original's |
| db | `python tools/build_db.py --game-src` | regenerates `db/functions.csv` and `docs/PROGRESSO.md` |

## Layout

```
orig/          your client's binaries (not in git; md5 in orig/README.md)
analysis/      facts extracted from the original (classes, EH, vtables; Core/Engine ones; Engine class layouts); analysis/ghidra/ = Ghidra export (generated, not in git)
db/            function database (functions.csv generated) + hand-written names, notes and checks; the C1 → C2 port maps
include/ue2/   declarations of the C2 Core.dll/Engine.dll, checked against the exports
include/nwindow/, src/nwindow/    the decompiled source, one class per file
src/re/        hook-mode runtime (hook install, log, ini, CRT compatibility)
src/standalone/                   IMPLEMENT_CLASS / IMPLEMENT_PACKAGE, globals, NWindow.def, empty GameGuard, diagnostic logs
tests/         reference outputs (golden, still C1's) and standalone lists
third_party/ue_import/            .def of the Core/Engine exports (turned into .lib at build time)
tools/         analysis, C1 → C2 port (tools/port), install, judges, cycle
docs/          plan, conventions, progress and technical notes (Portuguese)
```
